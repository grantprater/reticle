The Ability Event Log

The pixel detector stalled at 0.36 precision, so the channel was re-founded on a supervisor that reads no minimap pixels at all: the HUD tray. This is what the log contains, where each field comes from, and the four answers an event is allowed to give.

§1 The log

prototypes/ability_cast.py --emit writes one event per cast to <store>/events/ability/. Not l2/ — stage 03 has no schema yet and this must not look like it is claiming one.

{ session_id, t_ms, source:"tray", slot, agent, ability, reusable,
  confidence:"clean"|"suspect",
  x, y, position_from, position_ambiguous,
  drivers:{origin, bearing, extent},   bearing, bearing_state,
  entities:[{origin_x, origin_y, bearing, n_fragments, extent}], n_entities,
  n_candidates, n_objects, candidates:[…], window_s, frame:"map", built_by }

The shape of the record comes from the minimap entity model, which is the companion to this document: an entity is an origin, an optional bearing, an extent, an existence, an anchor and a frame — with a driver per parameter rather than per object.

The event is the deliverable; the position is enrichment

A cast carries a time, a slot and an ability with no minimap evidence at all, and that is already usable. the instruction on this channel: ship partial identification. Detect > localise > classify, and emit what is known at each level rather than waiting. An ability that draws nothing on the widget still emits a real event — and those are exactly the ones no minimap detector can ever reach.

§2 The four answers an event may give

24 events over 6 labelled sessions. Every event lands in exactly one of these, and which one it lands in is the result.

11

One position

A single candidate, fragments of one object, or an extending object resolved to its origin.

1

Several entities

One cast, N objects. Sova's ult is three bolts from one origin, so no single x/y is the honest answer.

10

Refused

More than one candidate and nothing to choose on. x/y null; the candidates ride along for a later scorer.

2

No candidate

Often correct — a grenade, flash, molotov or dash draws nothing and is still a real cast.

Where a position is given it is right. Scored against the hand labels, leave-nothing-out: 3 / 3 exact, 0 px — small, and it is a selection accuracy rather than a detection one, since on these sessions the candidate file and the label file are largely the same positions.

for ult the tray cast should be the pips going hollow. Rendered and then measured, slot X goes 909 teal pixels → 0 between 28.0s and 28.5s against a first Hunter's Fury label at 28.2s — the pips desaturate along with the bar, so the existing teal mask reads them with no new geometry. §4 A cast buys the event, not the position

This document previously argued that inside a known cast window the candidate set would be small enough for a weak per-pixel score to suffice. Measured, it is not — and two attempts to fix it with a rule that looked principled both produced wrong answers:

rulewhat happened
nearest onset to the castcorrect picks stayed at 3 at every window width; median miss 0 → 36 px as the window grew. Only ever right where there was nothing to choose between.
earliest group = a piloted object's originthe same heuristic wearing a type. Put Skye's Trailblazer 79 px from its label.
the entity model's own signaturedistance from the origin increasing with time, over ≥3 distinct fragments. Resolved Toxic Screen correctly and produced its bearing.

So time and identity come free from HUD structure; location still needs a detector. That belongs beside the 63% wherever it is quoted. Ten events refuse a position and say so, which is the correct answer rather than a gap to fill with a guess.

§5 The extending entity, and why a cast is 1:N

Measured — abilities animate, and the animation traces the deployment vector

abilities have animations — quite a few extend along a line or region. So a wall's fragments are not one object that grew; they are the animation tracing the orientation, sharing a bearing from the origin with distance increasing over time. Viper's Toxic Screen: the onset rule split its window into 5 objects; the extending signature returns one entity at +9.7°, from 3 fragments, origin (243,367), and rejects the two candidates at −96° and −61°.

Independently checked on Sova's ult: the fitted bearings explain their labels to within 1.5–2.2°.

Ontology error, caught by the game's own data

The schema had room for one position per cast. Sova's Hunter's Fury is “three long-range, wall-piercing energy blasts … can be RE-USED up to two more times” — one cast, up to three separate extending objects, each with its own bearing. Treating the second as ambiguity was throwing away a real entity.

With the window widened for re-usable abilities the log returns three bolts from one origin: +38.4°, +78.2°, +164.7°. reusable is derived, not listed: 12 of the reference's 121 descriptions say RE-USE, and they are the right 12 — including both of Viper's, which is the resource-bar observation arriving from the game's text rather than from memory.

two caveats, both the The count is up to three, not three. The ult can be fired 0–3 times within the window, so three is what that cast did, never a spec to validate against — and an event with fewer is not a miss. And the window length is fitted, not derived. The description says re-use is allowed “while the ability timer is active” and the infobox does not give that timer, so the reference cannot supply it; 6.0s covers the 4.95s spread seen in one clip, which is a constant fitted to a single observation and should be re-measured on a second re-usable cast.

A bug worth naming, because it looked like a result

Widening that window first changed which bolts came back — +45°/+78° became +78°/+170°. That was not the window; it was greedy first-match clustering against a running mean, which is order-dependent, so one extra candidate at an intermediate bearing bridged two clusters. A result that moves when an unrelated candidate enters the window is not a measurement. Clustering by sorting bearings and splitting at gaps depends only on the set. The +78.2° cluster is now identical at both window widths.

§6 What the log rests on that no longer holds

Compressed, because it is settled. The labelling pass that was queued to unblock a weighted combiner instead falsified the numbers the channel was steered by.

claimwasis
patch_range pooled AUC0.860.57
best gate operating point0.49 @ 0.850.44 @ 0.45
blocker on a weighted combiner27 positivesnot label volume

The combiner was fitted on 85 positives across 9 sessions and loses to an equal-weight z-sum in every configuration, with 100% sign agreement across all 8 folds — stable, and still no better than weighting everything equally, which is what near-redundant features look like. Per-session z-scoring is worth more than any weighting (0.74 vs 0.64 AUC), so the dominant variance is per-session rather than per-object. And patch_range's collapse is perfectly confounded with capture regime, which one ordinary-capture session labelled the new way would settle.
